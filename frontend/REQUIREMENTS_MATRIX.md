# Проверка интеграции frontend с backend

Сверено с локальными роутерами `backend/src/api` проекта `F:/работа/project` на 26.09.2026.
Архивная версия backend не использовалась. Живая проверка HTTP невозможна без запущенного
сервера, базы данных и S3-хранилища.

| Сценарий | Контракт | Состояние frontend |
|---|---|---|
| История и открытие плана | `GET /api/plans`, `/api/plans/{id}` | Подключено; открытие версии загружает её данные |
| Детали заявки и инженера | `GET /api/requests/{id}`, `/api/engineers/{id}` | Подключено |
| Первичный импорт | `POST /api/planning/initial` | Подключено, в auto-режиме тоже отправляется в API |
| Перепланирование | `POST /api/planning/replan` | Подключено |
| Срочная заявка и событие дня | `POST /api/planning/events` | Подключено, payload соответствует типу события |
| Утверждение плана | `POST /api/plans/{id}/approve` | Подключено |
| XLSX плана | `GET /api/plans/{id}/export` | Подключено через подписанный URL |
| Дневные PDF | `GET /api/reports/daily` | Подключено; возвращается ZIP-архив |
| Ручное назначение | Endpoint отсутствует | Кнопки заблокированы в API-режиме |
| Фактический статус заявки | Endpoint отсутствует | Контрол заблокирован в API-режиме |
| Полный аудит действий | Endpoint отсутствует | Показывается только история версий плана |

Метрики в аналитике и сравнении рассчитываются из данных API; выдуманные проценты, время
расчёта и пробег по версиям удалены. Карта использует MapGL 2ГИС и координаты плана.
Требуется интеграционный прогон с реально поднятым backend до утверждения о готовности продукта.
