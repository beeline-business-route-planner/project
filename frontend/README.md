# Диспетчерская выездных инженеров

Frontend хакатонного решения «билайн»: контроль рабочего дня, карта заявок и
маршрутов, планирование и перепланирование, журнал, аналитика и отчёты.

Интерфейс использует чёрно-жёлтый визуальный код билайн, шрифт Onest и акцентные иконки Phosphor. Полная сверка
технического задания, ответов экспертов и API приведена в
[`REQUIREMENTS_MATRIX.md`](./REQUIREMENTS_MATRIX.md).

## Запуск

```bash
npm install
copy .env.example .env
npm run dev
```

Приложение откроется на `http://localhost:5173`.

По умолчанию `VITE_DEMO_MODE=auto`: интерфейс сначала пытается подключиться к backend по
`VITE_API_BASE_URL`, а если backend недоступен — показывает связный демонстрационный
сценарий и показывает предупреждение. В автоматическом fallback операции не имитируют успешный ответ backend. Для защиты без backend установите `VITE_DEMO_MODE=true`. Для строгого режима без
fallback установите `VITE_DEMO_MODE=false`.

Карта работает через официальный MapGL JS API 2ГИС. Добавьте в локальный `.env` ключ из
кабинета 2ГИС: `VITE_2GIS_KEY=...`. Файл `.env` игнорируется Git, поэтому ключ не попадёт
в коммит.

## Основные сценарии

- `Контроль дня`: статусы заявок, фильтрация, карта, выбор заявки или инженера, просмотр
  маршрута, создание срочной заявки через событие. Редактирование фактического статуса доступно только в демо: endpoint backend отсутствует.
- `Планирование`: импорт пары XLSX одного округа (заявки и инженеры), перепланирование, история версий, сравнение связанных планов,
  события рабочего дня и утверждение черновика. Ручное назначение пока недоступно: backend не публикует такой endpoint.
- `Журнал и отчёты`: метрики плана, загрузка инженеров, сравнение версий, история версий,
  выгрузка XLSX-плана и ZIP-архива дневных PDF-отчётов.

## Интеграция

API-клиент находится в `src/api`. `GET /api/plans/{plan_id}` отдаёт
сохранённый порядок остановок, координаты и метрики. При выборе инженера frontend
запрашивает `GET /api/plans/{plan_id}/engineers/{engineer_id}/route` и рисует
геометрию Routing API 2ГИС для его типа транспорта. Геометрия строится по запросу и
не меняет сохранённые метрики плана. Если 2ГИС недоступен или ключ не даёт доступа к
Routing API, карта показывает ошибку без прямой линии между остановками.
Списки версий берутся из
`GET /api/plans?region=...`, карточки заявок и квалификации — из актуальных
`GET /api/requests/{id}` и `GET /api/engineers/{id}`.

Импорт подключён к `POST /api/planning/initial` с двумя multipart-полями `files`: книгой заявок и книгой инженеров одного округа. В переданном организаторами датасете книги инженеров нет; файл «Контрольное распределение» не является её заменой.
Перепланирование использует `/api/planning/replan`, события — `/api/planning/events`,
утверждение — `/api/plans/{id}/approve`. Выгрузки используют URL, возвращённые
`/api/plans/{id}/export` и `/api/reports/daily`. Отдельных endpoint для ручного назначения,
фиксации фактического статуса и полного аудита backend пока не предоставляет.

При локальном запуске Vite отправляет `/api` через proxy на `http://127.0.0.1:8000`;
даже если старый `.env` содержит `http://localhost:8000/api`, в dev-режиме адрес
автоматически переводится на этот proxy. В production нужен reverse proxy для `/api`
или настроенный CORS и абсолютный `VITE_API_BASE_URL`.

При запуске в API-режиме необходимо поднять backend и его зависимости по инструкции backend.
Без запущенного API фронтенд покажет демонстрационные данные, но это не подтверждение
работы интеграции. Ключ 2ГИС, помещённый в `VITE_2GIS_KEY`, передаётся в браузер и не
является серверным секретом; для публичного использования ограничьте его по домену в кабинете 2ГИС.

Переданный исходный датасет датирован 17.08.2026. Текущий backend использует фактическое
время сервера как отсечку расчёта и не предоставляет параметр даты для симуляции.
Поэтому полноценный сквозной тест планирования этого исторического дня потребует
согласованного режима симуляции в backend или нового датасета на текущий день.

Detailed-route выбранного инженера формируется из уже загруженного снимка плана, поэтому
повторный выбор инженера не создаёт новый HTTP-запрос.

Все координаты API и MapGL ожидаются в формате `[longitude, latitude]`.
