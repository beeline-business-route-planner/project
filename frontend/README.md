# Диспетчерская выездных инженеров

Frontend хакатонного решения «Билайн Бизнес»: контроль рабочего дня, карта заявок и
маршрутов, планирование и перепланирование, журнал, аналитика и отчёты.

Интерфейс использует актуальный чёрно-жёлтый визуальный код билайн бизнес. Полная сверка
технического задания, ответов экспертов и API приведена в
[`REQUIREMENTS_MATRIX.md`](./REQUIREMENTS_MATRIX.md).

## Запуск

```bash
npm install
copy .env.example .env
npm run dev
```

Приложение откроется на `http://localhost:5173`.

По умолчанию `VITE_DEMO_MODE=auto`: интерфейс сначала пытается подключиться к backend по
`VITE_API_BASE_URL`, а если backend недоступен — показывает связный демонстрационный
сценарий. Для защиты без backend установите `VITE_DEMO_MODE=true`. Для строгого режима без
fallback установите `VITE_DEMO_MODE=false`.

## Основные сценарии

- `Контроль дня`: статусы заявок, фильтрация, карта, выбор заявки или инженера, просмотр
  маршрута и ручная фиксация факта.
- `Планирование`: импорт Excel, запуск расчёта, история версий, сравнение планов, ручная
  правка, событие перепланирования и утверждение черновика.
- `Журнал и отчёты`: метрики, загрузка инженеров, сравнение версий, аудит, выгрузки XLSX и
  PDF.

## Интеграция

API-клиент находится в `src/api`. Маршруты для общей карты загружаются через
актуальный `GET /api/plans/{plan_id}`: frontend строит обзор из `engineers[].stops`,
координат и метрик сохранённого плана. Списки версий берутся из
`GET /api/plans?region=...`, карточки заявок и квалификации — из актуальных
`GET /api/requests/{id}` и `GET /api/engineers/{id}`.

Импорт подключён к `POST /api/planning/initial` с массивом multipart-полей `files`.
Действия, для которых backend ещё не опубликовал endpoint (утверждение, события,
редактирование статуса и отчёты), не отправляют ложные запросы: интерфейс сообщает о
текущем ограничении API.

Detailed-route выбранного инженера формируется из уже загруженного снимка плана, поэтому
повторный выбор инженера не создаёт новый HTTP-запрос.

Все координаты API ожидаются в формате `[longitude, latitude]`; перед передачей в Leaflet
они преобразуются в `[latitude, longitude]`.
