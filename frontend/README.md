# Frontend диспетчера

React + TypeScript + Vite: контроль дня, карта заявок и инженеров, создание и
утверждение планов, история версий и отчёты. Загрузка данных и действия
сосредоточены в `src/hooks/usePlanner.ts`. Действующий backend-контракт
открывается в `/docs` запущенного API; карта приложения и запуск всего стека —
в [корневом README](../README.md).

## Запуск

```bash
cd frontend
npm ci
cp -n .env.example .env
npm run dev
```

Открыть <http://localhost:5173>. Vite проксирует `/api` на backend
`127.0.0.1:8000`; он запускается отдельно по [`backend/README.md`](../backend/README.md).
В локальном `.env` укажите браузерный `VITE_2GIS_KEY` для MapGL — он доступен в
браузере, ограничьте его по домену в кабинете 2ГИС. Ключ линий маршрутов
`DGIS_ROUTING_KEY` остаётся в dev-сервере (Vite проксирует `/dgis-routing` на 2ГИС
и сам добавляет ключ). `.env` не коммитьте. Production-сборка — `Dockerfile` (nginx),
запуск всего проекта — корневой `docker compose up -d --build`.

Для проверки **реального** API установите `VITE_DEMO_MODE=false`: режим `auto`
переходит к демоданным, только если недоступен `/api/ping`. Если backend отвечает,
но планов нет, показывается пустое API-состояние, не вымышленные заявки. `true` —
принудительное демо. Без backend или актуальных XLSX сегодняшнего дня сквозное
планирование проверить нельзя.

Контроль дня умеет менять статус заявки через `PATCH /api/requests/{id}/status`;
отмена выполняется через событие планирования. Ручное планирование доступно
после загрузки XLSX, а рассчитанный кандидат можно исправить до утверждения.
На карте план даёт точки; дорогу между ними для выбранного
инженера браузер запрашивает через прокси `/dgis-routing` у 2ГИС Routing / Public Transport API (машина, пешком,
велосипед, общественный транспорт); участки без маршрута видны красным пунктиром.

## Проверка и навигация

```bash
npm run typecheck
npm run build
```

`src/api/` — HTTP и типы, `src/hooks/usePlanner.ts` — загрузка и адаптация данных,
`src/pages/` — экраны, `src/components/MapPanel.tsx` — карта. Матрица требований и
исторических решений — [`REQUIREMENTS_MATRIX.md`](REQUIREMENTS_MATRIX.md), но для
фактического поведения ориентируйтесь на код и backend OpenAPI.
