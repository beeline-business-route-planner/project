# Материалы кейса «Билайн Бизнес»

Эта папка хранит материалы, полученные от организаторов хакатона, и краткие навигационные
документы к ним. Она не описывает устройство конкретного backend или frontend.

## Приоритет источников

При расхождении применять следующий порядок:

1. официальное ТЗ `source_files/Билайн Бизнес.pdf`;
2. официальные уточнения заказчика: `source_files/QA_2.md` и ответы представителей
   заказчика в `source_files/transcript_clean.txt`;
3. актуальные продуктовые user cases проекта в `../backend/docs/user-case/` — они
   конкретизируют неоднозначные или не заданные организаторами детали, но не отменяют ТЗ;
4. `source_files/TECHNICAL_CONSTRAINTS.md` и `source_files/SUMMARY.md` — поддерживаемые
   командой выжимки первоисточников;
5. `team_discussions/` — исторический контекст внутренних решений. При расхождении с
   актуальными user cases использовать user cases.

Официальное более позднее уточнение трактуется как разъяснение соответствующего положения
ТЗ. Если оно выглядит как прямое противоречие ТЗ, решение нельзя выбирать молча: нужно
зафиксировать конфликт и согласовать трактовку.

## Что читать агенту

- Для быстрого понимания обязательных полей и ограничений —
  [`source_files/TECHNICAL_CONSTRAINTS.md`](./source_files/TECHNICAL_CONSTRAINTS.md).
- Для смысла и происхождения каждого переданного файла —
  [`source_files/README.md`](./source_files/README.md).
- Для уточнений заказчика по темам —
  [`source_files/SUMMARY.md`](./source_files/SUMMARY.md).
- Для проверки точной формулировки — официальный PDF, `QA_2.md` или транскрипт.
- Внутренние PDF созвонов и `team_discussions/SUMMARY.md` читать только ради истории
  решения, а не как актуальную продуктовую спецификацию.

Не нужно сканировать все PDF, транскрипты и Excel для каждой задачи. Сначала достаточно
этого README и профильной выжимки; к сырому источнику обращаются при споре, необходимости
точной цитаты или проверке структуры данных.

## Как трактовать переданные Excel

| Материал | Роль |
|---|---|
| `<Регион> Синтетические данные.xlsx` | Штатные входные данные заявок. Слово «синтетические» не делает файл тестовым или необязательным. |
| `<Регион> Контрольное распределение.xlsx` | Справочный пример ручного распределения заявок диспетчером; не входной список инженеров, не эталон результата и не источник характеристик инженеров. |
| `Нормативы.xlsx` | Официальная таблица длительности работ и состава норматива. |

В переданном наборе нет полноценной отдельной книги доступных инженеров с требуемыми ТЗ
полями: стартовой точкой, сменой, 1–3 навыками и транспортом. Поэтому актуальный user case
добавляет отдельную входную книгу инженеров. Это проектная конкретизация недостающего
формата, а не утверждение, что такой файл был передан организаторами.

Имя Excel предназначено для человека и не является машинным контрактом. При импорте роль
книги определяется по обязательным колонкам; нужные поля извлекаются, дополнительные
колонки игнорируются. Округ определяется из содержимого книги.

## Состав папки

- `source_files/` — официальные исходные материалы и поддерживаемые выжимки к ним;
- `team_discussions/` — протоколы ранних внутренних обсуждений команды;
- `GITFLOW.md` — процесс разработки проекта, не требование заказчика.
