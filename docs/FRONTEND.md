# Frontend: экраны, данные и интеграция

React + TypeScript + Vite в `frontend/` — рабочее место диспетчера поверх
[действующего backend API](BACKEND.md). Экран показывает один выбранный округ и
день, хотя backend умеет импортировать несколько округов одним запросом.

## Что делает диспетчер

| Экран | Реальные действия и данные |
|---|---|
| Контроль дня | Список заявок/инженеров, фильтры, карта, карточки из `GET /api/requests/{id}` и `/engineers/{id}`. Статус заявки сегодняшнего дня меняется через `PATCH /api/requests/{id}/status`; отмена вынесена в событие. |
| Планирование | Загрузка **одной пары** XLSX одного округа → `POST /api/planning/initial`; обычный перерасчёт → `/planning/replan`; внештатное событие → `/planning/events`. Версии открываются через `/plans/{id}`, решение — `/approve` или `/reject`; diff сравнивает связанные версии. |
| Журнал / аналитика | История из `GET /api/plans?region=...`, показатели из сохранённых планов. XLSX версии и ZIP дневных PDF загружаются по подписанным ссылкам из `/plans/{id}/export` и `/reports/daily`; CSV списка версий формируется локально. |

После импорта или перерасчёта появляется **кандидат** `pending`. Пока он не
утверждён, `GET /api/plans/current` и обзор рабочего дня показывают последний
утверждённый план. В списке версий видны также отклонённые кандидаты. Если API
вернул региональную ошибку внутри HTTP 200, UI должен показать её пользователю;
сам по себе успешный HTTP-статус не означает успешного планирования.

Сейчас нет backend endpoint для ручного назначения заявки инженеру: видимая форма
не должна восприниматься как сохранение реального назначения. «История действий»
собирается из истории версий и их статусов, а не из отдельного audit API. В
принудительном demo-режиме часть действий показывает демонстрационный сценарий,
но не меняет сервер.

## Карта и маршруты

`GET /api/plans/{id}` отдаёт `engineers[].stops` с координатами, порядком,
плановым временем и расстояниями. Это **точки маршрута**, не геометрия дорог.
MapGL показывает карту и маркеры; при выборе инженера компонент `MapPanel` отдельно
обращается к 2ГИС Directions и рисует линию по дорогам. Для пешего транспорта
используется pedestrian route, для остальных — car route; отдельной геометрии
велосипеда или общественного транспорта в UI сейчас нет. Сервис Directions имеет
лимиты и требует доступного браузерного ключа. Если он не отвечает, точки плана
могут отображаться без линии. Повторный расчёт плана backend при выборе инженера
не происходит. Координаты в MapGL передаются как `[longitude, latitude]`.

`VITE_2GIS_KEY` нужен карте; `VITE_2GIS_DIRECTIONS_KEY` — отдельный ключ для дорог,
если он задан, иначе используется основной. Любой `VITE_*` ключ попадает в
браузерный bundle: ограничивайте его по домену в кабинете 2ГИС.

## Запуск и режимы данных

```bash
cd frontend
npm ci
cp .env.example .env
npm run dev
```

Адрес — <http://localhost:5173>. Локальный Vite proxy передаёт `/api` на backend
`127.0.0.1:8000`. Backend и его зависимости запускаются отдельно по
[`backend/README.md`](../backend/README.md). Значения `frontend/.env`:

- `VITE_API_BASE_URL=/api` — базовый путь API; для production нужен reverse proxy
  либо явный URL и разрешённый CORS.
- `VITE_DEMO_MODE=false` — строгая проверка backend; при ошибке не подменять
  реальные данные демоданными. `auto` (значение по умолчанию) может перейти в
  демо при недоступности API/плана; `true` включает демонстрацию принудительно.
- `VITE_2GIS_KEY`, опционально `VITE_2GIS_DIRECTIONS_KEY` — карта и дороги.

Чтобы вручную проверить интеграцию, используйте `VITE_DEMO_MODE=false`, рабочие
ключи и XLSX **на текущий московский день**. Историческая книга без режима
симуляции в backend не подтверждает сквозной сценарий. Проверки frontend:
`npm run typecheck` и `npm run build`.

## Где менять код

| Потребность | Файлы |
|---|---|
| Переходы между экранами и общий shell | `src/App.tsx`, `src/components/Shell.tsx` |
| HTTP-клиент, методы, backend-типы | `src/api/client.ts`, `services.ts`, `types.ts` |
| Загрузка плана, адаптация API в UI-модель, операции | `src/hooks/usePlanner.ts` |
| Контроль, планирование, журнал | `src/pages/Dashboard.tsx`, `Planning.tsx`, `Journal.tsx` |
| Карта и 2ГИС Directions | `src/components/MapPanel.tsx` |
| Dev proxy и сборка | `vite.config.ts`, `package.json` |

Схема слоёв всего проекта — [ARCHITECTURE.md](ARCHITECTURE.md). Для нового API-метода
сначала сверяйте backend OpenAPI и `src/api/types.ts`, затем адаптацию в `usePlanner`;
иначе экран может показать старую демо-модель вместо серверного состояния.
