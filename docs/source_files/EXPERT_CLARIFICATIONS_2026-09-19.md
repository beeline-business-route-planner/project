1. Кто фиксирует факт выполнения или отмены заявки? Как учитывать закрытые заявки при перераспределении?

Факт закрытия заявки фиксируется диспетчером на основании информации от бригады. Закрытые заявки считаются выполненными и при дальнейшем перераспределении в планирование не включаются.

2. Возможно ли перепланирование заявок в течение рабочего дня?

Да, перепланирование в течение дня возможно.

При перепланировании необходимо учитывать приоритеты разных типов работ. Например, заявка на подключение может иметь более высокий приоритет, чем заявка на ремонт, а аварийная заявка может потребовать оперативного изменения текущего маршрута.

При изменении расписания ранее озвученное клиенту время может быть скорректировано. Коммуникация с клиентом в этом случае осуществляется службой поддержки.

3. Нужно ли самостоятельно моделировать компетенции инженеров и транспорт?

Да. Если необходимых данных нет в исходном наборе, команда может самостоятельно смоделировать характеристики бригад, необходимые для работы алгоритма.

4. Как учитывать оборудование при распределении заявок?

Бригада получает оборудование в офисе сразу на весь рабочий день.

При перепланировании на бригаду могут назначаться только те заявки, для выполнения которых у неё имеется необходимое оборудование. Допустимый запас оборудования можно определить самостоятельно в рамках модели.

5. Как учитывать аварийные заявки: весь день или норматив 100 минут?

Для расчётов следует использовать норматив выполнения аварийной заявки 100 минут.

При этом начало выполнения аварийной заявки определяется временем её фактического поступления. То есть авария возникает в течение рабочего дня и может повлиять на дальнейшее расписание бригады.

6. Что означают ВК и HD?

ВК в рамках датасета относится к Beekeeper. HD означает HelpDesk, стороннюю систему, из которой поступает заявка.

Таким образом, это не два разных вида работ, а обозначения, относящиеся к разным системам.

7. Как связаны тип заявки ВК и тип заявки HD?

Поля относятся к разным системам и могут использовать разные классификаторы одной заявки. При построении решения команда может определить необходимое соответствие между ними исходя из предоставленных данных.

8. Меняются ли статусы заявки в течение рабочего дня?

Да. Статус заявки изменяется по мере её выполнения.

Основные состояния: «Отправлено» — заявка поступила исполнителю; «В пути» — бригада направляется к месту выполнения; далее заявка переходит к выполнению; «Завершено» — работы закончены. Статус «Отменена» может появиться при отказе клиента либо когда бригада определила, что выполнить заявку невозможно.

9. Должен ли алгоритм быть динамическим?

Для выполнения задачи хакатона достаточно статического планирования, то есть построения расписания на основании исходной выгрузки.

При этом поддержка динамического перепланирования в течение рабочего дня допустима и может быть дополнительной возможностью решения.

10. Какие компетенции должны быть у бригад?

Команды могут самостоятельно определить модель компетенций. За основу можно взять типы работ, которые конкретная бригада имеет право выполнять.

Например, можно определить, что только часть бригад имеет квалификацию для выполнения ремонтов или аварийных работ.

Ключевое ограничение: если у бригады отсутствует необходимая квалификация, она считается неспособной выполнить соответствующий тип работ. Такие заявки назначаться на эту бригаду не должны.

Дополнительные компетенции и уровни квалификации команды могут вводить самостоятельно, если считают их полезными для алгоритма распределения.


11. Какой перекос по типам заявок и квалификациям использовать?

В материалах представлены два набора данных:

* Контрольная выборка отражает фактическое распределение заявок и работу бригад в один из реальных дней сентября в Москве на рассматриваемых участках.
* Синтетическая выборка содержит очищенный набор заявок, который можно использовать для построения собственного распределения.
Количество бригад команда может определить самостоятельно. Количество бригад из контрольной выборки можно использовать как ориентир.

Если команда самостоятельно синтезирует данные, можно использовать примерно следующее распределение типов заявок: 40% локальных заявок, 40% подключений, 10% аварий и 10% дозаказов.

12. Можно ли использовать количество бригад из контрольного распределения как ориентир?

Да. Количество бригад из контрольного распределения можно использовать как ориентир для формирования собственного набора исполнителей. При этом команда может самостоятельно определить необходимое количество бригад для своего алгоритма.

13. Откуда стартуют бригады в удалённом Подмосковье?

Для бригад, обслуживающих удалённые города Подмосковья, например Каширу, Ступино или Домодедово, можно самостоятельно определить стартовую точку в соответствующем городе.

Такую точку предлагается считать «домом» исполнителя, откуда он начинает рабочий день. Использование фактических GPS-координат не требуется.

14. Как учитывать перемещение на общественном транспорте?

Допустимо использовать усреднённое время или скорость перемещения от точки до точки.

Расчёт реальных маршрутов общественного транспорта не является обязательным требованием или самостоятельной «победной фичей». При этом решение, способное учитывать комбинированные способы перемещения и реалистично рассчитывать маршруты для бригад без автомобиля, будет представлять дополнительный интерес при оценке.

15. Какие заявки приоритетнее при нехватке ресурсов?

Приоритет распределения следующий:

Авария → Подключение → Ремонт / Дозаказ.

Авария имеет максимальный приоритет. Если аварийная заявка появляется уже в течение рабочего дня, она может стать основанием для изменения ранее сформированного маршрута бригады.

Таким образом, алгоритм может предусматривать динамическое перепланирование при поступлении аварии, даже если базовый сценарий решения строится на статическом планировании рабочего дня.
