# Архитектурные решения

## ADR-001. Версии планов неизменяемы

Любой расчёт и ручная правка создают новый `draft` с `parent_plan_id` и `base_plan_id`. Утверждение
атомарно переводит прежний активный план в `superseded`. Если базовая версия изменилась, API
возвращает 409. Назначения старой версии не обновляются.

## ADR-002. Факты append-only

Расчётное время не создаёт фактический `COMPLETED`. Ручная демонстрационная корректировка добавляет
новую строку `request_status_events` с `source=demo_manual`, автором, временем факта, временем записи
и ссылкой на исправляемое событие.

## ADR-003. Провайдеры отделены портами

Геокодер, маршрутизатор и алгоритм не импортируют SQLAlchemy или FastAPI. По умолчанию включены
явно названные demo-адаптеры. Основной профиль использует 2ГИС Geocoder, Distance Matrix и Routing API через один
конфигурируемый ключ, но с раздельной диагностикой scope. Nominatim/OSRM сохранены как явно выбираемые адаптеры. Яндекс
не выдаёт фиктивный успех: без коммерческого контракта/ключа возвращает диагностируемый 503.

## ADR-004. Норматив дороги не суммируется с маршрутом

В план входит рассчитанное провайдером время дороги и работа на месте 70/80/20/30 минут. Полный
норматив 90/100/40/50 хранится для аналитики. Неизвестная пара BK/HD получает `needs_mapping`.

## ADR-005. Дата демонстрации независима от системных часов

Снимок получает явные `planning_date` и `as_of`; системное время доступно только через порт `Clock`.
Это делает 17.08.2026 воспроизводимой датой. Внутри хранилища timestamps записываются в UTC, а
бизнес-интерпретация использует `Europe/Moscow`.
