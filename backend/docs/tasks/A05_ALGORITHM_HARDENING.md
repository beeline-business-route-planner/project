# A05. Финальная стабилизация алгоритмической дорожки

## Владелец и зависимости

- Владелец: Algorithm.
- Требует: A01–A04.
- Не ждёт G04, но предоставляет результат для G05.

## Цель

Стабилизировать единый algorithm facade, аудит и метрики для всех трёх сценариев без
расширения продуктового scope.

## Объём работ

1. Унифицировать input/output initial/replan/event replan.
2. Устранить временные adapters и старые методы, которые сохраняют Plan.
3. Проверить детерминизм при фиксированных входах и matrix.
4. Унифицировать audit errors и причины unassigned.
5. Проверить метрики:
   - total/route mileage;
   - work minutes;
   - travel minutes;
   - utilization относительно смены с дорогой и без неё;
   - assigned/unassigned;
   - engineers used.
6. Проверить граничные случаи MVP: ноль назначений, один инженер, все заявки
   неназначены, cutoff в конце смены, unreachable point, пустой future tail.
7. Зафиксировать version идентификаторы optimized и baseline реализаций.
8. Не оптимизировать производительность ценой нарушения hard constraints; бюджет и
   fallback должны возвращать аудируемый полный результат.

## Критерии приёмки

1. Backend использует один facade без знания конкретной стратегии.
2. Нет SQLAlchemy/FastAPI/S3 зависимостей внутри вычислительного слоя.
3. Все результаты проходят общий аудит.
4. Метрики одинаково определены во всех сценариях.
5. `make check` проходит.
