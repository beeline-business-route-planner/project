# T06. Excel-выгрузка любого плана

## Цель

Сформировать согласованный XLSX для любого existing plan независимо от его статуса и вида.
Diff в Excel не включается.

## Исполнитель и зависимости

- Исполнитель: Backend B.
- Требует: G02.
- Параллельно: T05 и A03.
- Блокирует: T09, но не G03.

## HTTP API

`GET /api/plans/{plan_id}/export`

Endpoint загружает immutable snapshot конкретного plan ID. Он не подменяет его current и
не запрещает экспорт pending/rejected.

## Структура workbook

1. Лист всех заявок:
   - идентификаторы и исходные поля;
   - assigned/unassigned;
   - исполнитель;
   - sequence;
   - planned arrival/start/finish;
   - travel/distance;
   - unassigned reason.
2. Лист всех инженеров:
   - данные смены и транспорта;
   - число заявок;
   - работа/дорога/пробег;
   - utilization с дорогой и без неё.
3. Отдельный лист каждого инженера со всеми его stops в порядке маршрута.
4. Безопасные уникальные имена листов с учётом ограничений XLSX.
5. Metadata plan: region, day, kind, status, created/approved time и metrics.

## Технические требования

- использовать уже подключённый `openpyxl`, не добавлять новую библиотеку;
- генератор получает snapshot DTO, а не делает собственные SQL-запросы;
- вывод детерминирован;
- timezone/datetime формат одинаков во всех листах;
- файл валиден даже при нуле assigned stops;
- содержимое diff не дублируется.

## Не входит

- выгрузка нескольких планов одним XLSX;
- новые форматы CSV/ODS;
- permanent storage;
- дневной отчёт.

## Критерии приёмки

1. Экспортируются initial/replan/event и все lifecycle statuses.
2. Workbook открывается и содержит обязательные листы.
3. Суммы по инженерам совпадают с plan metrics.
4. Срочная заявка без upload присутствует.
5. Названия листов валидны и уникальны.
6. `make check` проходит.
