# A03. Алгоритм обычного replan

## Владелец и зависимости

- Владелец: Algorithm.
- Требует: A01.
- Не зависит от backend T05/T06.
- Нужен для G03.

## Цель

Получить полный новый план дня, сохранив фактически прожитое прошлое current-плана и
пересчитав только допустимый будущий хвост.

## Вход

- полный approved base snapshot;
- актуальные заявки/инженеры и их состояния;
- единый `calculation_cutoff_at`;
- routing matrix;
- режим распределения.

## Объём работ

1. Классифицировать stops как locked по согласованным временным правилам.
2. Скопировать locked stops без изменения инженера, sequence относительно истории,
   request, arrival/start/finish, travel и distance.
3. Вычислить фактическую стартовую позицию/время будущего хвоста каждого инженера после
   locked history.
4. Пересчитать только mutable requests.
5. Не назначать новые действия раньше cutoff.
6. Вернуть полный snapshot: locked history + future tail + unassigned.
7. Сохранить явный `is_locked` в выходных stops.
8. Выполнить тот же аудит полноты и физических ограничений, что для initial, плюс
   byte-semantic equality locked stops с base.

## Граница

- Алгоритм не выбирает base/current.
- Алгоритм не решает, можно ли approve устаревший кандидат.
- Алгоритм не строит diff и не сохраняет Plan.
- Алгоритм не обрабатывает event payload в этой задаче.

## Критерии приёмки

1. Ни одна locked stop не изменяется.
2. Future tail начинается из корректного состояния после истории.
3. Полный результат содержит каждую заявку ровно один раз.
4. Остановка, ставшая прошлой к cutoff, не пересчитывается.
5. Результат совместим с pure output A01.
6. `make check` проходит.
