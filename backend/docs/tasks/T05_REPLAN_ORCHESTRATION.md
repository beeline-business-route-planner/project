# T05. Backend orchestration обычного replan

## Цель

Реализовать синхронный пересчёт одного или нескольких округов от их собственного current
approved-плана с независимым результатом по каждому округу.

## Исполнитель и зависимости

- Исполнитель: Backend A.
- Требует: G02.
- Параллельно: T06 и A03.
- Блокирует: G03.

## HTTP API

`POST /api/planning/replan` получает непустой список уникальных регионов. Новый Excel и
ручные изменения маршрута не принимаются.

## Объём работ

Для каждого региона независимо:

1. определить текущую московскую рабочую дату и зафиксировать единый cutoff;
2. загрузить current approved plan региона/дня;
3. при отсутствии approved initial/current вернуть региональную conflict-ошибку;
4. собрать полный нормализованный snapshot current;
5. вызвать replan-контракт A03;
6. выполнить аудит результата;
7. сохранить новый полный `pending` Plan с `kind = replan`;
8. записать `based_on_plan_id = current.id` и тот же исходный upload;
9. сохранить copied locked history и пересчитанный future tail;
10. вернуть summary/error в общей структуре partial success.

## Инварианты

- база выбирается на момент начала регионального расчёта и фиксируется ID;
- pending/rejected никогда не становятся базой;
- кандидат не изменяет current до approve;
- весь день хранится полным snapshot, а не patch;
- прошлые и начатые stops являются точными locked-копиями;
- новый кандидат может существовать рядом с другими pending;
- diff не сохраняется: detail построит его от `based_on_plan_id`.

## Транзакционность

Каждый регион — независимая транзакция. Ошибка одного региона не откатывает кандидатов
других и отражается в региональном результате.

## Не входит

- события;
- ручное редактирование;
- force approve;
- новый upload;
- алгоритмическое распределение.

## Критерии приёмки

1. Можно запросить один или несколько регионов.
2. Каждый успешный результат имеет правильный current в `based_on_plan_id`.
3. Ни один locked stop не изменён.
4. Результат — pending и не влияет на current.
5. Detail вычисляет diff, list возвращает summary.
6. Partial success не теряет успешные планы.
7. `make check` проходит.
