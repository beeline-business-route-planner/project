# T08. Генерация дневных PDF-отчётов

## Цель

Сформировать по запросу плановый отчёт о дне: отдельный PDF каждого участвовавшего
региона и один общий summary PDF.

## Исполнитель и зависимости

- Исполнитель: Backend B.
- Требует: G03.
- Параллельно: T07 и A04.
- Блокирует: T09, но не G04.

## Входной контракт

Генератор получает report snapshot за `planning_date`, собранный сервисом из approved
данных. PDF renderer не делает собственные SQL-запросы и не знает pending/rejected.

## Состав регионального PDF

- регион и рабочая дата;
- approved initial и время утверждения;
- хронология всех approved replans;
- approved внештатные события и время;
- последний approved полный план на момент запроса;
- все инженеры и их итоговые маршруты;
- assigned/unassigned и причины;
- plan mileage;
- work/travel time;
- utilization инженера относительно смены с дорогой и без неё;
- региональные агрегаты и сравнение optimized initial с baseline.

## Summary PDF

- список участвовавших регионов;
- сводные количества заявок/инженеров;
- суммарный пробег;
- assigned/unassigned;
- utilization с дорогой и без неё;
- число approved replans/events;
- сравнение initial с baseline по регионам.

## Семантика

- отчёт можно вызвать в середине дня;
- используются все approved планы/события, доступные на момент запроса;
- итоговый маршрут берётся из последнего approved snapshot, который содержит историю;
- pending/rejected не включаются;
- отчёт является плановым, не утверждает фактическое исполнение;
- отсутствие данных региона не создаёт пустой региональный PDF.

## Технические ограничения

Выбор PDF-библиотеки является новой зависимостью и должен быть отдельно согласован до её
добавления. Задача включает renderer, но не должна молча добавлять инфраструктуру или
системные бинарники.

## Не входит

- actual tracking;
- Excel diff;
- фоновая генерация;
- закрытие рабочего дня;
- S3/ZIP доставка — T09.

## Критерии приёмки

1. N участвовавших регионов дают N PDF + 1 summary.
2. Pending/rejected нигде не попадают в отчёт.
3. Метрики совпадают с последним approved snapshot.
4. Отчёт корректен в середине дня.
5. Кириллица и таблицы читаемы, страницы не обрезают данные.
6. `make check` проходит.
