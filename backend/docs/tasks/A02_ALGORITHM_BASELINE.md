# A02. Отдельный baseline-алгоритм

## Владелец и зависимости

- Владелец: Algorithm.
- Требует: T00 и стабильные нормализованные input DTO A01.
- Не зависит от T01–T04.
- Блокирует полноценный G02.

## Цель

Реализовать отдельный примитивный контрольный алгоритм для сравнения initial. Он не
является Plan и не использует `is_baseline`.

## Объём работ

1. Выделить отдельную реализацию baseline, не режим optimized planner.
2. Получать те же заявки, инженеров, routing matrix и cutoff, что основной initial.
3. Соблюдать те же hard constraints и классификацию unassigned.
4. Использовать простой детерминированный принцип распределения, зафиксированный внутри
   реализации и version label результата.
5. Вернуть метрики, необходимые для сравнения:
   - mileage;
   - engineers used;
   - assigned/unassigned;
   - work/travel minutes;
   - utilization with/without travel.
6. Полные маршруты могут существовать в памяти для аудита, но backend сохраняет только
   отдельный `BaselineResult`, а не рабочий Plan/PlanStop.

## Инварианты

- запускается только для initial;
- не имеет approval status;
- не участвует в current/history/diff;
- не является базой replan;
- сравнение честное: одинаковые входные данные, cutoff и hard constraints.

## Критерии приёмки

1. Нет использования `Plan.is_baseline`.
2. Результат можно связать один-к-одному с initial через backend.
3. Повторный расчёт детерминирован.
4. Нарушение hard constraint ловится аудитом.
5. `make check` проходит.
