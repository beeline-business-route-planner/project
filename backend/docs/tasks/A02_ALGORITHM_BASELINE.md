# A02. Независимый baseline initial

## Владелец и зависимости

- Владелец: Algorithm.
- Требует: A00 и стабильные DTO A01.
- Не зависит от T01–T04.
- Блокирует полноценный G02.

## Цель

Дать простой воспроизводимый контрольный расчёт, с которым сравнивается основной initial.
Baseline не является третьим режимом и не сохраняется как `Plan`.

## Объём работ

1. Получать тот же snapshot, cutoff и набор матриц, что optimized planner.
2. Соблюдать те же SLA и hard constraints.
3. Буквально соблюдать п. 2.3 ТЗ: обходить заявки в порядке входного snapshot, выбирать
   первого во входном порядке подходящего инженера и добавлять заявку только в конец его
   маршрута. Не сортировать по приоритету, не искать лучшего инженера, не использовать
   граф, перестановки или greedy completion.
4. Применять ту же материализацию и независимый аудит.
5. Возвращать version label и метрики:
   - assigned/unassigned;
   - engineers used;
   - service/travel minutes;
   - mileage;
   - utilization with/without travel.
6. Сохранять через backend только `BaselineResult`, связанный с initial plan.

## Инварианты

- baseline запускается только для initial;
- не имеет approval status и не участвует в current/history/diff;
- не является базой replan;
- сравнение использует идентичные входы и hard constraints.

## Критерии приёмки

1. Нет использования `Plan.is_baseline`.
2. Повторный расчёт детерминирован.
3. Baseline проходит тот же auditor.
4. Результат связан один-к-одному с initial через backend.
5. `make check` проходит.
