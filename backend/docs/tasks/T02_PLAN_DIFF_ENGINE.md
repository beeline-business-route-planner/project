# T02. Чистый движок диффа планов

## Цель

Реализовать детерминированное сравнение двух полных снимков плана без запросов к БД,
HTTP и знания lifecycle. Дифф не хранится.

## Исполнитель и зависимости

- Исполнитель: Backend B.
- Зависимость: T00.
- Параллельно: T01, A01/A02.
- Блокирует: G01.

## Входной контракт

Функция получает два immutable snapshot:

- `before` — утверждённый план, указанный кандидатом в `based_on_plan_id`;
- `after` — pending-кандидат.

Каждый snapshot содержит всех инженеров, assigned stops, unassigned requests, времена,
последовательность, travel, distance и агрегатные метрики. Diff-функция не ищет
«последний план» самостоятельно.

## Объём работ

1. Создать чистые DTO snapshot/diff в домене plans.
2. Для инженеров классифицировать:
   - `added`;
   - `removed`;
   - `unchanged`;
   - `changed`.
3. Внутри каждого инженера классифицировать заявки:
   - осталась без изменений;
   - добавлена;
   - удалена;
   - перенесена другому инженеру;
   - изменена по времени;
   - изменена по позиции;
   - изменены travel/distance;
   - перешла assigned ↔ unassigned.
4. Для изменённых значений вернуть `before` и `after`; для чистого удаления достаточно
   исходного значения, для добавления — нового.
5. Рассчитать summary delta:
   - mileage;
   - число используемых инженеров;
   - assigned/unassigned;
   - время работы;
   - время дороги;
   - загрузка с дорогой и без неё.
6. Обеспечить стабильный порядок инженеров и заявок, не зависящий от порядка входных
   коллекций.
7. Initial не сравнивается: вызывающая сторона вернёт `diff = null`.

## Не входит

- загрузка plan из БД;
- выбор current/base;
- lifecycle;
- отдельный endpoint диффа;
- Excel/PDF представление;
- произвольное сравнение любых пользовательских plans.

## Изоляция от T01

Задача владеет новым pure-модулем diff и его API DTO. Она не меняет ORM, миграции,
repositories или UoW. Сведение DTO с persistence выполняется в G01.

## Проверочные сценарии

- полностью одинаковые планы;
- новый/удалённый инженер;
- заявка передана другому инженеру;
- изменились только arrival/start/finish;
- изменились только дорога/километраж;
- заявка стала неназначенной и обратно;
- входные массивы случайно переставлены, результат идентичен.

## Критерии приёмки

1. Результат полностью соответствует разделу «Дифф» user case.
2. В модуле нет I/O и зависимости от SQLAlchemy/FastAPI.
3. Diff вычисляется для размеров MVP без отдельного кэша или таблицы.
4. Все поля before/after однозначны.
5. `make check` проходит.
