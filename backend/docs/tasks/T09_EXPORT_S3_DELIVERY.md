# T09. ZIP и временная доставка экспортов через S3

## Цель

Объединить сгенерированные файлы отчёта в один скачиваемый пакет и выдавать экспорты через
временные S3-объекты без постоянного хранения на backend filesystem.

## Исполнитель и зависимости

- Исполнитель: Backend B.
- Требует: T06 и T08.
- Может выполняться параллельно G04 после готовности входов.
- Блокирует: G05.

## HTTP API

- `GET /api/plans/{plan_id}/export` использует единый механизм доставки XLSX;
- `GET /api/reports/daily?planning_date=...` генерирует пакет дневного отчёта.

## Объём работ

1. Расширить S3 storage операцией создания presigned download URL.
2. Сформировать ZIP дневного отчёта:
   - один PDF на каждый участвовавший регион;
   - один summary PDF;
   - детерминированные безопасные имена файлов.
3. Сгенерированный XLSX/PDF/ZIP сразу загрузить в отдельный export bucket/prefix.
4. Вернуть download metadata и временную URL.
5. Настройки typed config:
   - bucket/prefix;
   - URL TTL;
   - lifecycle retention;
   - максимальный размер.
6. Не сохранять бинарники в БД и не оставлять постоянные локальные файлы.
7. Ошибка upload/presign возвращает согласованную API-ошибку и не выдаёт битую ссылку.
8. Настройка lifecycle самого S3 документируется как внешняя инфраструктурная
   предпосылка; backend не симулирует удаление по таймеру внутри HTTP-запроса.

## Не входит

- permanent archive;
- список ранее созданных отчётов;
- background jobs;
- новые форматы экспорта.

## Критерии приёмки

1. План выдаёт валидный XLSX по временной ссылке.
2. День с N регионами выдаёт ZIP из N+1 PDF.
3. URL истекает по config, а не литералу.
4. Локальные временные файлы гарантированно очищаются при успехе и ошибке.
5. S3 failure отображается контролируемой ошибкой.
6. `make check` проходит.
