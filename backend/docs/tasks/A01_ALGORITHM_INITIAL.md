# A01. Алгоритм initial с фактическим временным срезом

## Владелец

Algorithm. После T00 задача не зависит от backend-дорожек.

## Цель

Превратить initial в чистый вычислительный контракт: на входе snapshot + единый cutoff,
на выходе полный проверяемый план без commit и lifecycle-решений.

## Объём работ

1. Определить публичный input/output алгоритма независимо от ORM и FastAPI.
2. Принимать `calculation_cutoff_at` явно; не вызывать `now()` внутри стратегий.
3. Для initial считать начало движения каждого инженера не раньше `max(shift_start,
   cutoff)`.
4. Не создавать arrival/start/finish в прошлом относительно cutoff.
5. Сохранить обязательные ограничения навыка, транспорта, окна заявки и смены.
6. Вернуть:
   - маршруты всех используемых инженеров;
   - materialized arrival/start/finish/travel/distance;
   - unassigned с публичной причиной;
   - агрегатные метрики;
   - данные для загрузки с дорогой и без неё.
7. Добавить аудит результата до возврата:
   - заявка ровно один раз assigned или unassigned;
   - нет дубликатов;
   - последовательность непрерывна;
   - времена монотонны и физически выполнимы;
   - соблюдены ограничения.
8. Убрать commit Plan из AlgorithmService: persistence принадлежит backend orchestration.

## Граница

- Алгоритм не знает `pending/approved/rejected`.
- Алгоритм не выбирает current.
- Алгоритм не строит API schemas или diff.
- Алгоритм не сохраняет S3/БД.

## Критерии приёмки

1. Расчёт в 10:12 не содержит новых действий раньше 10:12.
2. Один input даёт детерминированный результат при одинаковом routing matrix.
3. Невозможные заявки имеют согласованные причины unassigned.
4. Backend может вызвать контракт без передачи SQLAlchemy entities.
5. `make check` проходит.
