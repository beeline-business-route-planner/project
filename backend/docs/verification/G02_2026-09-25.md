### 2.1 Попытка с настоящим 2ГИС — BLOCKED

Ключ был предоставлен пользователем и виден приложению (`dgis_key_present=True`); его значение не сохранено в репозитории и не приводится здесь. Запрос:

```bash
curl -F 'files=@vostok_requests.xlsx' -F 'files=@vostok_engineers.xlsx' \
  http://127.0.0.1:58000/api/planning/initial
```

HTTP `200`, результат округа `{"region":"vostok","status":"error","error":{"code":"routing_unavailable","detail":"Маршрутизация недоступна"}}`. Отдельный короткий запрос к `https://routing.api.2gis.com/get_dist_matrix` завершился `ConnectTimeout`; `curl` вернул `SSL_ERROR_SYSCALL`, HTTP `000`. Следовательно, окружение не установило соединение с API 2ГИС и не проверило пригодность ключа. После неуспешной загрузки в БД было по `0` записей `dataupload`, `uploadedfile`, `request`, `engineer`, `plan`, `baselineresult`; в трёх тестовых бакетах — по `0` объектов. Это подтверждает rollback и очистку для сбоя маршрутизации.

### 2.3 Частичный успех и очистка файлов — PASS с локальным ответчиком маршрутов

В новой пустой БД `g02_test_http_partial_20260925` применена та же миграция. Использованы отдельные бакеты `g02-partial-uploads`, `g02-partial-answers`, `g02-partial-plans`. Одним `POST /api/planning/initial` переданы шесть файлов: по паре заявок и инженеров для трёх округов. Для Юго-востока намеренно создано имя инженера длиной более 255 символов: книга проходит парсер, а сохранение данных после загрузки файлов вызывает ошибку ограничения БД. Это контролируемый сбой, позволяющий проверить rollback и очистку объектов.

```bash
curl -F 'files=@vostok_requests.xlsx' -F 'files=@vostok_engineers.xlsx' \
  -F 'files=@yugo_vostok_requests.xlsx' -F 'files=@yugo_vostok_engineers.xlsx' \
  -F 'files=@yugotsentr_requests.xlsx' -F 'files=@yugotsentr_engineers.xlsx' \
  http://127.0.0.1:58000/api/planning/initial
```

HTTP `200`, общий `status=partial_success`: `vostok=success` (план `01a0d921-c87a-700c-b6b0-381cb6ef23c5`), `yugo_vostok=error` (`internal_error`), `yugotsentr=success` (план `01a0d921-dfcb-7309-9232-96c83ac80fc5`). В БД: `dataupload=2`, `uploadedfile=4`, `request=2`, `engineer=2`, `plan=2`, `planstop=2`, `baselineresult=2`; планы и загрузки есть только для Востока и Югоцентра, по два файла на округ. В MinIO осталось ровно четыре объекта в `g02-partial-uploads` (20767 байт), в других двух бакетах — ноль. Множество ключей всех объектов MinIO точно совпало с четырьмя `uploadedfile.s3_key` в БД (`exact_match=True`): файлов неуспешного округа не осталось.
