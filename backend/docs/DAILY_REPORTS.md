# Плановые PDF-отчёты дня (T08)

`DailyReportService.build_snapshot(planning_date)` собирает immutable report snapshot из
утверждённых планов и событий. Он не пишет в БД и не обращается к S3. Для
воспроизводимых проверок можно передать `generated_at` с часовым поясом; при обычном
вызове используется текущее московское время.

`DailyPdfRenderer.render(snapshot)` получает только snapshot и возвращает словарь
`{filename: pdf_bytes}`: один `<region>.pdf` на каждый округ с approved планом и
`summary.pdf` всегда. Renderer не выполняет SQL-запросы. HTTP, ZIP и S3-доставка
относятся к T09.

В отчёт попадают планы и события со статусом `approved` на момент формирования.
Событие включается, если его связанный план тоже входит в утверждённый срез.
Последний approved план даёт полный итоговый маршрут, а initial даёт показатели для
сравнения с сохранённым baseline. Если у approved initial нет baseline или сохранённые
агрегаты плана не совпадают с его маршрутами, генерация останавливается с ошибкой
целостности данных, а не создаёт неверный отчёт.

Загрузка инженера считается как `(работа [+ дорога]) / длительность смены * 100`.
Региональный показатель — среднее по доступным инженерам последнего плана, как в
`GET /api/plans/{id}`. Сводный показатель — среднее по доступным инженерам всех
участвовавших округов. Время в PDF показывается по Москве. Отчёт плановый и не
утверждает фактического выполнения заявок.

PDF рисуется на ReportLab в стиле интерфейса: жёлтый акцент, графитовый текст, шрифт Onest
(Regular/Medium/SemiBold/Bold, статические начертания из вариативного шрифта Google Fonts,
лицензия OFL) лежит в `src/api/reports/assets/`, поэтому PDF с кириллицей не зависит от
системных шрифтов контейнера. Визуальные блоки (KPI-карточки, сравнение с baseline,
структура времени, таймлайн смены, хронология) — в `src/api/reports/pdf_components.py`.

Отчёт по округу: обзор (KPI, initial против baseline, структура рабочего времени), таймлайн
смены по инженерам, хронология утверждённых планов и событий, причины неназначения и
маршруты инженеров. Сводный отчёт: общие KPI, карточки округов, сравнение с baseline и
структура времени по округам, итоговая таблица.

Для интеграционной проверки нужна отдельная пустая PostgreSQL `t08_test_*` с применёнными
миграциями. Тест запускается с явным `T08_TEST_DATABASE_URL`:

```bash
T08_TEST_DATABASE_URL='postgresql+asyncpg://USER:PASSWORD@127.0.0.1:5433/t08_test_example' \
  uv run python -m unittest tests.test_t08_daily_reports -v
```

Тест создаёт два округа, approved initial и event replan, а также pending/rejected
кандидаты. Он проверяет фильтрацию, метрики, день в середине смены и рендер PDF.
